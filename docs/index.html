RoastMC

Multiloader Minecraft server software. One project, one jar, your choice of NeoForge or Fabric, with Bukkit-style plugins on top.

Overview

EditionModsPlugin APISource
NeoForgeNeoForgePaper / PurpurRepository root
FabricFabricSpigotfabric/

Current target: Minecraft 26.2, Java 25.

Fabric and NeoForge cannot run inside the same Minecraft. A server runs one edition at a time. To use Fabric mods on the NeoForge edition, see Fabric mods on NeoForge.

Install and run

You need Java 25, one RoastMC jar, and an empty folder for the server. Do not double-click the jar: the server needs a console window, so start it from a script or a terminal as shown below.

1. Get the jar

  • From GitHub Actions: open the Build workflow, open the latest successful run, and download RoastMC-26.2 from the Artifacts section at the bottom. You must be signed in to GitHub. It downloads as a .zip; extract it to get roastmc-26.2-all.jar.
  • Build it yourself: see Building from source.

Use the -all jar. It contains both editions and lets you pick the loader in server.properties (see Choosing the loader).

2. Run on Windows

  1. Install Java 25. Download the Windows .msi for JDK 25 from Adoptium (x64). In the installer, enable Add to PATH and Set JAVA_HOME.
  2. Check it worked. Open a new Command Prompt or PowerShell window and run: 
    java -version
    It should print a version starting with 25. If Windows says 'java' is not recognized, close and reopen the window, or reinstall with Add to PATH enabled.
  3. Make a server folder, for example C:\RoastMC, and put roastmc-26.2-all.jar in it.
  4. Create the start script. In Notepad, paste: 
    @echo off
java -Xmx4G -jar roastmc-26.2-all.jar nogui
pause
    Choose File → Save As, set Save as type to All files, and name it start.bat in the same folder. (If you save as "Text document" you get start.bat.txt, which will not run. In File Explorer, turn on View → Show → File name extensions to check.)
  5. Start the server. Double-click start.bat. The first start downloads Minecraft and libraries and then stops because of the EULA. This is normal.
  6. Accept the EULA. Open eula.txt in Notepad, change eula=false to eula=true, save, and double-click start.bat again.
  7. Allow network access. If Windows Defender Firewall asks, allow Java on private networks, and on public networks too if friends outside your home network will join. To host over the internet, forward TCP port 25565 on your router to this PC.
  8. Join. In Minecraft, add the server as localhost if you are on the same PC, or use your PC's local or public IP address.

To stop the server cleanly, type stop in its window and press Enter. Closing the window or pressing Ctrl+C may skip the world save.

Change -Xmx4G to use more or less memory, for example -Xmx6G. Do not give it more than your PC can spare.

Run on Linux or macOS

Install Java 25 (for example from Adoptium or your package manager), then:

mkdir roastmc && cd roastmc
# put roastmc-26.2-all.jar here
java -Xmx4G -jar roastmc-26.2-all.jar nogui

As on Windows, set eula=true in eula.txt after the first start and run it again. To keep it running after you close the terminal, use screen or tmux.

3. After the first start

  • server.properties now contains the loader keys neoforge, fabric and paper. Edit them and restart to switch loader.
  • Put mods in mods/ and plugins in plugins/, then restart.
  • Downloaded libraries and the unpacked editions live in libraries/. You can delete that folder to force a clean re-download.

Choosing the loader

The unified jar reads three keys from server.properties. They are added automatically on first start. Edit them and restart to switch.

neoforge=true
fabric=false
paper=true
neoforgefabricStarts
truefalseNeoForge edition (Paper/Purpur API)
falsetrueFabric edition (Spigot API)
truetrueNeoForge edition plus Sinytra Connector, so Fabric mods load too
falsefalseRefuses to start

paper cannot be disabled on the NeoForge edition, because the Paper API is part of it, so paper=false is ignored with a warning. With only fabric=true, paper=true has no effect because the Fabric edition uses the Spigot API.

Each edition runs in its own JVM. Your JVM arguments (such as -Xmx) and program arguments (such as nogui) are passed through.

Fabric mods on NeoForge

With neoforge=true and fabric=true, the launcher sets up Sinytra Connector, a compatibility layer that runs Fabric mods on NeoForge.

  • It downloads Connector and its required dependencies (Forgified Fabric API, Launchpad) from Modrinth into mods/ for the running Minecraft version.
  • Downloads are checked against Modrinth's SHA-512 hashes. Nothing is installed unless every required piece exists.
  • Files are tracked in mods/.roastmc-connector and updated on later starts.
  • A Connector jar you placed in mods/ yourself is left alone.
  • If Modrinth has no build for your Minecraft version, or is unreachable, the server starts without Fabric support and prints why.
Experimental, does not start yet. Connector and its dependencies download and load, but the server then stops with a Mixin error such as Critical injection failure ... beforeAddEffect ... fabric-entity-events-v1. Forgified Fabric API patches vanilla methods, and RoastMC's Bukkit patches change some of those methods (for example LivingEntity.addEffect gains a Bukkit cause parameter), so the patch targets no longer exist. Each such mismatch needs a compatibility fix inside RoastMC, and one is enough to stop startup. Until that is done, keep fabric=false when neoforge=true, or use neoforge=false and fabric=true to run the Fabric edition.
Connector is also a third-party project and still in beta, and not every Fabric mod works. Check connector.sinytra.org for mod compatibility.

Configuration

Everything is in one place. Only server.properties (including the neoforge, fabric and paper loader keys) lives next to the jar; every other setting is under config/:

server.properties          loader keys + normal Minecraft settings
config/
  roastmc/                 RoastMC's own settings
    roastmc.yml            main RoastMC options
    database.yml, commands.yml, menu/ ...
  bukkit.yml  spigot.yml  purpur.yml  commands.yml     plugin API settings
  paper-global.yml  paper-world-defaults.yml           Paper settings
  neoforge-common.toml  neoforge-server.toml  fml.toml  NeoForge settings
  (and one file per mod)

You will usually only touch config/roastmc/roastmc.yml and, for plugins, the file named after the API you are tuning. Servers from older versions are migrated automatically on first start: bukkit.yml, spigot.yml, purpur.yml and commands.yml are moved from the server folder into config/, and roastmc-config/ becomes config/roastmc/. Nothing is overwritten.

Main groups in config/roastmc/roastmc.yml (NeoForge edition):

Key prefixWhat it controls
roastmc.*Language (roastmc.lang), startup logo, library check, auto-delete of server-incompatible mods
anvilfix.*Maximum repair cost and enchantment levels
keepinventory.*Keep inventory and XP, globally or by permission
entity.clear.*Periodic clearing of dropped items and monsters, with whitelists and messages
bans.*Banning items, blocks, entities, enchantments, recipes, worlds, structures and effects
events.*Fire tick, explosions, join and quit messages
custom.*Misc tweaks: villagers, spawners, sign commands, lava speed, end/nether teleport of entities
player_modlist_blacklist.*Block clients that have blacklisted mods
backup_world.*Scheduled world backups (interval, maximum number, zstd)
networkmanager.*, pluginchannel.*, permissions.debug.*Debug output

The file is commented and lists every option. The Fabric edition currently creates no extra config files.

Commands

NeoForge edition. Each command is gated by a permission node roastmc.command.<name>.

CommandPurpose
/roastmcServer tools: info, mods, playermods, reload, version, modchannels, speed, printthreadcost, packetstats, heal, cleardropitem, memoryfix, showp, backupworld, migratedb, help
/dumpDump server data: potions, enchants, entitytypes, biomes, material, channels, advancements, and more
/itemsItem tools: name, save, list, get, give, remove, lore, attribute, rarity, modeldata
/permission checkCheck a permission
/bansManage the ban lists configured under bans.*
/shows, /infosExtra information commands

Run /roastmc help in game or console for the full list for your version.

Building from source

Requires JDK 25 and about 4 GB of free RAM for Minecraft decompilation.

./gradlew setup          # first time only
./gradlew roastmcAllJar

The result is one jar, multiloader/build/libs/roastmc-26.2-all.jar, containing both the NeoForge and Fabric editions. The editions are built as part of it. The Fabric edition is a separate Gradle build (Fabric Loom cannot share a build with the NeoForge toolchain) that the root build includes with includeBuild. Run ./gradlew :multiloader:test for the launcher's unit tests.

Troubleshooting

"Neither 'neoforge' nor 'fabric' is enabled"

Set at least one of them to true in server.properties.

"has no NeoForge build for Minecraft ... yet"

Connector and its dependencies are not published for your Minecraft version. The server runs without Fabric support. Use a Minecraft version Connector supports, or wait for a release.

Fabric mods crash or are ignored

Confirm fabric=true and neoforge=true, that the three Connector jars are in mods/, and that the mod is supported by Connector. Remove mods one at a time to find the culprit.

The window flashes and closes (Windows)

Run start.bat from a Command Prompt (cd C:\RoastMC, then start.bat) to read the error. The script ends with pause, so if the window still closes instantly, the file may really be start.bat.txt.

"RoastMC needs Java 25 or newer"

Your Java is too old (for example Java 21). Install Java 25, then run java -version in a new window and confirm it shows 25. If it still shows an older version, an older Java is earlier on your PATH: uninstall it, or start the server with the full path to the new one, such as "C:\Program Files\Eclipse Adoptium\jdk-25...\bin\java.exe" -jar ....

"UnsupportedClassVersionError ... class file version 69.0"

Same cause, from a build made before the Java check was added. Install Java 25.

Port already in use

Another server is already using port 25565. Close it, or change server-port in server.properties.

Out of memory while starting

Raise -Xmx, for example java -Xmx6G -jar ....

Switching loaders on an existing world

Back up first. Worlds and mod data created under one loader are not guaranteed to load under the other.
